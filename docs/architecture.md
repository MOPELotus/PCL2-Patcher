# 实现与兼容边界

`src/PclPatcher.Core` 实现分析、引用重绑定、IL 复制、写后核验和文件事务；`src/PclPatcher.Cli` 负责命令行与 JSON；`tools/PclPatcher.Audit` 只为独立验证提取嵌入程序集，不运行启动器；`tests/PclPatcher.Tests` 使用真实官方输入及其结构变体。

## 五个补丁的验证

恢复前要求 ILOnly、无强名称签名、可执行入口、程序集标识为 Plain Craft Launcher 2，并验证 donor 的外部依赖身份可用于目标。类型/签名只用于缩小搜索范围，不单凭符号存在或限制提示字符串决定成功。

1. 自动安装：匹配异常 LoaderTask 的完整构造结构、字段缓存与分支边、最终三指令异常闭包。替换后整个方法必须与旧版无限制方法语义相等。
2. 文件选择：根据 donor 构造“闭包创建 + Hint + return”的已知受限投影；整个目标方法（含局部变量和异常区域）必须匹配。恢复官方文件选择与 RunInThread 逻辑。
3. 分派：找到包含七种具体安装器的 switch 与覆盖它的外层 finally，用已知异常替换该区间并删除正常返回，形成受限投影。目标必须完整匹配该投影；不能把任意 throw 当作可以删除的限制。
4. 资源按钮：找到资源类型判定且分支中存在安装回调的区间，构造只有 Save 的受限投影；完整方法比较后才恢复。
5. 修改页面：准确定位 get_CardMinecraft 与 set_Visibility 的参数，构造 Collapsed 投影，完整方法比较后才恢复 Visible。

匹配将短/长分支、参数/局部变量宏编码统一化，并忽略保留控制流目标的 NOP；规范化在副本上执行，不因检测改写输入方法。比较包括局部变量类型、分支/switch 目标及 catch/finally 范围。恢复方法体中的所有指令、局部变量、参数、分支与 EH 边界均复制并重新绑定，不复制 donor 的元数据 token。

生成的 VB 适配器按签名和递归方法体语义寻找等价目标；同一签名可有多个完全等价的适配器。捕获闭包的已有函数也必须一致。泛型实例上的 MemberRef 另外核对其底层定义，避免仅导入同名引用而没有可调用成员。

## 写入后检查

先保存输入的所有方法语义、程序集身份、类型/成员结构及两份嵌入资源的摘要。dnlib 以 PreserveAll 元数据模式写临时 EXE，随后重新加载并要求：

- 每个改变的方法能解析，分支和 EH 边界属于其自身方法体，栈深分析成功，写出后 IL 等于计划。
- 再次执行五处功能分析应得到 restored。
- 非目标方法语义、程序集结构、资源内容与原始输入一致；包括登录/身份认证及其 UI 资源。

栈深分析不是完整 CLR 类型验证，因此独立验证脚本另外调用 Microsoft ILVerify；Windows CI 另做真实 .NET Framework 的 Load/JIT 准备检查。上述任何检查都不等同于实际下载、微软登录或图形界面验收。

## 文件事务

分析与临时写入成功后才建立原始备份。既有备份必须与输入一致，恢复记录也必须匹配。记录在替换前持久化，使中断后能够识别原始与已修补两种状态。同目录原子替换后重新核对最终 SHA-256；普通异常会回滚原始字节。自动化测试注入替换后的 I/O 异常验证精确恢复和重试。

恢复时仅接受恢复记录里的原始/修补摘要，备份必须通过摘要验证；不存在忽略完整性或覆盖未知文件的开关。摘要用于检测文件误改，不是数字签名或文件来源认证。

## 已知边界

不是通用反混淆器、任意版本方法移植器或运行时 Hook。未来版本保留相同受限投影与可调用 API 时可自适配；未知类型改名、安装算法变化、外部依赖身份变化、不同编译器控制流、移除的底层安装器都会被拒绝。新增限制如果不用已知提示或以完全不同方式实现，无法单靠当前五个模式证明它不存在，必须重新调查官方实际发布物。

donor 由用户提供或通过固定官方来源 fetch，工具不会鉴定任意用户提供文件是否官方；推荐只使用下载校验过的 2.14.0.0。正常修补所依赖的代码和资源均来自用户本地官方程序集。
